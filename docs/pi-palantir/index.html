Layer 2 · The harness

A Pi harness,
built for Palantir.

pi-palantir wraps the Pi coding agent with what Foundry work needs: the selected stack, ontology, and projects in every turn, and guardrails before any write. Every Foundry call goes through Orthanc.

Version
0.4.0
Runs on
Pi 0.84 or later
Needs
orthanc on your PATH

01Install

Install Pi and Orthanc first, then add the harness.

1 · Pi

The coding agent the harness runs in.

npm i -g @earendil-works/pi-coding-agent

2 · Orthanc

The CLI the harness uses for every Foundry call. See Orthanc.

curl -fsSL https://github.com/zaycruz/orthanc/releases/latest/download/install.sh | sh

3 · The harness

Loads the extensions, skills, and subagents into Pi. Onboarding runs on first launch.

pi install git:github.com/zaycruz/pi-palantir

02What's in it

The real component names, as they appear in the code.

Scope & context

Pickers choose the stack, ontology, and projects. They are injected into every turn, and older tool results are compacted.

Orthanc tools

orthanc_help and orthanc_cli are the one path to Foundry. Output must be a foundry-agent-v1 envelope.

Approval ladder

Four modes set with /approval: ask-always, allow-edits, auto (the default), and yolo. Destructive calls ask in every mode.

Branch gate

Classifies each write. Writes to protected targets like main and production ontologies ask in every mode except yolo.

Jev risk judge

In auto mode it decides ordinary writes: approve runs, ask or deny asks you. If it is unavailable, the harness asks.

Loop guard

Blocks a third identical tool call and tells the agent to use the evidence it has or change the experiment.

Subagents

Scout, builder, reviewer, and oracle, each with one job. The builder is the single writer.

Traces & evals

OpenTelemetry traces with secrets redacted at the source, and offline evals scored by rule.

03Changelog

Recent releases.

0.4.02026-09-21
  • New approval ladder replaces work roles. Pick a mode with /approval: ask-always, allow-edits, auto (the default), or yolo. The /role command is removed.
  • Guarded actions open an approval prompt instead of being blocked with no way forward. Destructive actions always ask, in every mode.
  • If the AI risk check is unavailable, the harness now asks for approval instead of letting the action through.
  • The Foundry MCP server is disconnected. All Foundry writes go through the Orthanc CLI.
  • MCP servers can declare themselves read-only in mcp.json, and tool-discovery calls are treated as reads.
  • Command risk levels now come from Orthanc's own manifest, so read-only commands are no longer blocked as if they were writes.
0.3.42026-09-20
  • Agents can clone Foundry repositories locally through Orthanc. The harness tracks each clone and shows it in the agent's context.
  • Cloning no longer needs a working branch first, and creating a branch in a session now correctly unlocks branch-scoped changes.
0.3.32026-09-20
  • Reads Foundry credentials saved by orthanc onboarding and orthanc auth store, with a fallback to older profiles. This fixes startup failures on fresh installs.
0.3.22026-09-20
  • Orthanc-first: Orthanc is now the main Foundry CLI, used through orthanc_cli and orthanc_help with live usage hints and checks after each change. The launcher is renamed to pi-palantir.
  • Branch safety: changes must target a working branch, and writes to main branches or production ontologies are blocked.
  • AI pre-tool guard checks risky tool calls before they run.
  • Safer memory: only the harness can save lessons, after a quality check. Doubtful entries are held for review.
  • Lower token use: large tool results are capped, with --output to save the full result to a file, and a loop guard redirects agents that repeat the same call.
  • New native commands: cp, osdk context, and notepad create. link-type-list now finds incoming links.
