Changelog

Assets and checksums for each release are on GitHub.

v0.3.52026-10-12
  • Linux credential storage: configure, onboarding and auth store the token in the Secret Service over D-Bus, or in a 0600 file, ~/.config/foundry/orthanc-credentials.json, on a host without one. ORTHANC_CREDENTIAL_STORE=auto|secret-service|file picks the store. On Linux the installer runs onboarding again, and it stores credentials from FOUNDRY_HOST and FOUNDRY_TOKEN only with ORTHANC_ONBOARD_FROM_ENV=1.
  • New repository imports add and remove: change what a repository imports: object types, link types, functions and the ontology. A source add only plans in this release.
  • New connectivity code-import get, set and remove-importer: whether code may import a source, its API name, and the code that imports it. dev-console connect now lists every type and function in an application's scope, and dev-console scope add and remove plan a scope change.
  • repository push fetches a commit that Foundry CI added after a push and refuses with a rebase hint. repository checks wait waits for the published function version after a tag check, bounded by --publish-grace.
  • sql execute and sql export stay read-only because Foundry refuses every write statement. The documentation cites this, and the live tests check it again.
v0.3.42026-10-12
  • Breaking: repository pull-request list now takes the repository RID and filters on the server with --status, --head and --base-branch, so it no longer times out on large stacks. proposal list uses the same path.
  • macOS release binaries are signed with a Developer ID and notarized, so the Keychain stops asking again after each update.
  • New ontology branch-index and branch-index-status: index the types an action edits on a global branch, so ontology action-apply --branch stops failing with ObjectTypeOrLinkTypeNotIndexed. ontology action-validate --branch validates on a branch. ontology definition --as-update now carries rule set bindings and type groups.
  • Repositories: new repository pull-request update, repository imports get, and repository git-credential, a Git credential helper for existing clones.
  • New notepad create and notepad append, both plan-first, and notepad get reads the live document. New media-sets list-items and media-sets info.
  • Also in this release: orchestration builds create --fallback-branch, orchestration jobs get --details, evals suite update, evals suite get --definition-out, and agent-manifest entries with descriptions, flags and examples.
v0.3.32026-10-08
  • New global-branch add-repo: links a code repository to a global branch and returns the Git ref that Foundry makes for it. Run it before repository tag create --foundry-branch-rid to publish a function version on a global branch. Without the link, the tag fails with FOUNDRY_BRANCH_NOT_FOUND, even for a valid, open branch.
  • repository tag create now tells you to run global-branch add-repo when a branch tag fails with FOUNDRY_BRANCH_NOT_FOUND.
  • The link can add an empty commit to the linked ref. Merge your work into that ref, then tag the merged commit.
v0.3.22026-10-01
  • New connectivity webhook list: shows the webhooks registered for a data connection source.
  • Safer applies: before --apply sends an ontology modify request, Orthanc re-reads the live entity on the branch the write actually targets and refuses with a usage error if the change would silently drop a live rule set binding, an inline action, or a webhook rule on an action type. Earlier builds compared the wrong branch in some branch-scoped applies.
  • The definition roundtrip documentation now states the verified wire limits: rule set bindings and inline actions travel as null, type groups as an empty list.
v0.3.12026-09-29
  • Fix: ontology definition --as-update roundtrips failed against real stacks with HTTP 400 and 422. Generated update documents now send the only shapes the modify endpoint accepts for these fields — ruleSetBinding and inlineAction as null, typeGroups as an empty list — so reading a type and writing it back works.
v0.3.02026-09-24
  • Breaking: every command that changes Foundry is plan-first. Without --apply it prints the exact request (verb, path, body) and changes nothing. The old --dry-run, --force, --confirm, and some --yes flags are replaced by --apply.
  • Breaking: configure no longer takes --token or --client-secret. Secrets come from --token-stdin, --client-secret-stdin, or a prompt, so they never appear in argv.
  • Breaking: removed the hosted LLM message and embedding commands, third-party-apps, and platform-sdk.
  • Ontology: ontology definition --as-update reads an object, action, or link type as an editable update document. Writes fill in the ontology version, target a global branch with --branch, and object-type-add-property takes simple flags.
  • Function release: repository checks list and checks wait, build-status, build-logs, functions versions, ontology action-type-set-function-version, repository create-typescript-functions, and container create.
  • compute info shows plain environment values and masks secret-like ones with a length and fingerprint. compute env get --to-file or --copy delivers a value without printing it.
  • A functional and end-to-end test suite covers every command and runs live against a Foundry stack. It found and fixed about 50 bugs, among them ontology writes that changed nothing and schema changes that made CSV datasets unreadable.
  • Also in this release: API names in agent output stay exactly as the platform returns them, repository tag commands, and a TLS library update for a published security advisory.
